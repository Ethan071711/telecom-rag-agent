# 电信请求意图分类 LoRA 实验

给现有客服项目补一个可复现的微调实验，学习如何冻结基座、训练小量适配参数、保存并重载适配器，以及比较微调前后结果。分类器暂未接入主问答流程，不会执行套餐、计费或推荐工具。

## 任务与数据

五类请求分别是业务知识、套餐查询、费用计算、套餐推荐和范围外问题。`data.json` 的语句由本项目合成编写，不包含真实客户信息。训练 100 条、验证 25 条、测试 50 条，各类平衡。三份数据无完全重复语句，在训练前固定；它们仍来自同一编写过程，不能称作真实用户独立测试。

`fee` 指已经选定套餐后的账单计算，`recommend` 指尚未选定套餐、按用量找最省钱方案。范围外包括企业专线、物联网卡、卫星电话、座机、云盘等本项目没有业务依据的请求。

## 实际训练与结果

使用固定版本的 [Qwen3-0.6B](https://huggingface.co/Qwen/Qwen3-0.6B)，基座提交 `c1899de289a04d12100db370d81485cdf75e47ca`；按 [PEFT 的 LoRA 流程](https://huggingface.co/docs/peft/en/quicktour)训练 q/v 投影的适配参数。rank 8、alpha 16、dropout 0.05、学习率 0.0002，固定 6 个 epoch、42 次优化器更新。提示词和填充 token 不计入损失。

2026-10-25，在本地 RTX 4070 Ti 上实际运行并重载保存的适配器：

| 固定 50 条合成测试语句 | 正确数 | 严格标签准确率 | Macro F1 | 格式无效输出 |
|---|---:|---:|---:|---:|
| 基座，相同固定零样本提示词 | 16/50 | 32% | 0.2825 | 3 |
| 重载 LoRA 适配器 | 48/50 | 96% | 0.9587 | 0 |

实际训练参数 1,146,880 个；纯训练阶段约 16.52 秒、峰值已分配显存约 3.13 GiB。该时间不含首次下载、模型加载或前后评测。逐题预测、混淆矩阵、验证集结果、训练损失、环境及数据/脚本哈希均在 [实测记录](../../results/lora_intent_20261025.json)。验证集结果为 22/25（88%）；另在新进程重载复测，50 条预测与原记录完全相同，见 [重载记录](../../results/lora_adapter_reload_20261025.json)。未按测试结果选超参数或检查点；保留了两个范围外请求被错分的错误。

这里展示的是这套小型合成数据上的适配效果。基座提示词没有单独调优，没有与其他强提示词或分类模型比较，不能据此声称通用模型能力或真实客服效果提升同样幅度。

## 运行

在项目根目录中，使用已有 GPU 环境或新虚拟环境安装可选依赖：

```powershell
python -m pip install -r experiments/lora_intent/requirements.txt
python experiments/lora_intent/predict.py "59元套餐用了80GB和350分钟，本月交多少？"
python experiments/lora_intent/train.py --output storage/lora-my-run
```

预测命令默认加载本目录的已保存适配器。首次运行还需要下载约 0.6B 参数的基座。训练命令写入指定实验目录，不覆盖已发布的结果文件。

本实验使用 BF16 基座和 LoRA，**没有进行 4-bit 量化，也没有运行 QLoRA**。SFT 是监督训练任务，LoRA 是参数高效适配方法，QLoRA 还涉及量化基座，两者不能互换。

训练脚本及新编数据按本仓库许可提供；基座与适配器遵循 Qwen3 的 Apache-2.0 许可，见适配器模型卡。运行不调用付费模型 API。
